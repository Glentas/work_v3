# Словарь данных `belstat_crime.sqlite`

База содержит 7 таблиц: **одну таблицу фактов**, **четыре справочника** и
**две служебные** таблицы. Всё, что лежит в CSV, дублируется здесь один в один —
База добавляет первичные ключи, индексы и возможность делать JOIN.

```
                         facts (19 990)
                   ┌──────────┼──────────────┐
             indicators  territories  dimension_values
                (29)        (374)          (899)
                   └──── dimensions (123) ──┘
                  meta (4)   errors (0)
```

Общее соглашение о пропусках: **NULL = «не применимо»**, пустых строк-заглушек
в базе нет.

| Таблица | Строк | Роль |
|---|---|---|
| `facts` | 19 990 | ядро: сами числа |
| `territories` | 374 | справочник территорий с иерархией |
| `indicators` | 29 | справочник показателей |
| `dimension_values` | 899 | значения всех справочников измерений (44 шт.) |
| `dimensions` | 123 | из каких измерений состоит каждый показатель |
| `meta` | 4 | параметры и итоги прогона |
| `errors` | 0 | журнал ошибок сбора |

---

## 1. `facts` — наблюдения

Одна строка = **одно официальное число**: показатель × год × территория ×
вариант разбивки. Это единственная таблица с данными; остальные — словари к ней.

Первичный ключ `fact_id`, 6 индексов (`indicator_code`, `geo_code`, `year`,
`region_code`, `district_code`, `breakdown_key`).

### Идентификация

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `fact_id` | TEXT PK | sha1(первые 32 символа) от естественного ключа `indicator_code\|time_period\|geo_code\|измерения…` | Делает перезапись идемпотентной: повторный прогон вставляет те же строки через `INSERT OR REPLACE`, дубликаты не накапливаются. Позволяет не заводить составной PK из 5–7 колонок. |
| `indicator_code` | TEXT NOT NULL | Код показателя на портале, напр. `10108000001` | Главный ключ отбора. FK → `indicators.indicator_code`. По нему же строится URL страницы портала. |
| `indicator_name_ru` | TEXT | Название показателя | Денормализация ради удобства: отчёты и выгрузки читаются без JOIN. Переводы (en/be) намеренно не дублируются в 20 тыс. строк — они в `indicators`. |

### Время

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `time_period` | TEXT NOT NULL | Период ровно так, как его отдал портал: `2024`, а для квартальных/месячных показателей было бы `2024-Q1` / `2024-05` | Универсальное поле: схема не ломается, если собрать рубрику с месячными данными. |
| `year` | INTEGER | Целый год, извлечённый из `time_period` | По нему работают индекс, группировки и фильтры `WHERE year = 2025`. В этом датасете всегда равен `time_period` — все 29 показателей годовые. |

### География

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `geo_code` | TEXT | Код территории из справочника `CL_razrez_594`. **NULL** у 832 строк — это показатели без территориального измерения (публикуются только в целом по стране) | FK → `territories.geo_code`. По коду, а не по названию, потому что названия неуникальны: `г. Полоцк` встречается дважды (район уровня 2 и посёлок уровня 3). |
| `geo_name_ru` | TEXT | Название территории | Читается без JOIN. |
| `geo_level` | INTEGER | `0` страна, `1` область/г. Минск, `2` район/город областного подчинения, `3` посёлок/сельсовет. NULL там же, где NULL у `geo_code` | Главный фильтр «какой уровень разреза». Позволяет не смешивать страну, области и районы в одной агрегации — иначе получится двойной счёт. |
| `geo_level_name` | TEXT | Текстовая подпись уровня, в т.ч. `без территориального разреза` | Для отчётов и графиков без перекодировки чисел. |
| `region_code` / `region_name_ru` | TEXT | Область-предок (уровень 1). NULL у страны и у строк без гео-разреза | Группировка «по областям» одним `GROUP BY region_name_ru` без рекурсивного обхода иерархии. |
| `district_code` / `district_name_ru` | TEXT | Район-предок (уровень 2). Заполнен у районов (совпадает с собственным кодом) и у посёлков уровня 3. NULL у страны и областей | Позволяет агрегировать посёлки в район и соединять данные с географией районов. |

Распределение по уровням в текущем датасете:

| `geo_level_name` | Строк | Территорий |
|---|---|---|
| Республика Беларусь | 4 826 | 1 |
| Область / г. Минск | 4 655 | 7 |
| Район / город областного подчинения | 9 677 | 128 |
| без территориального разреза | 832 | — |

### Разбивка (измерения)

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `breakdown_key` | TEXT | Машинный ключ всех негеографических измерений, отсортированный: `priznak_460=517692` или составной `priznak_10781=10,priznak_460=517667,priznak_462=517711,priznak_536=518105`. **NULL** у 3 784 строк — у показателя нет содержательной разбивки (например, «Уровень преступности на 100 000 человек») | Единый механизм для показателей с 0–4 измерениями. По нему фильтруют «только итоги» (`priznak_460=517667`) и по нему же идёт дедупликация. |
| `breakdown_value_ru` | TEXT | Человекочитаемое значение через ` / `: `кража`, `штраф / Всего по всем видам преступлений / Всего / По всем возрастам` | Чтобы не расшифровывать коды руками. Полные подписи с названиями измерений и переводы — в `dimension_values`. |

216 различных `breakdown_key`. Для главного показателя (`10108000001`):
13 видов преступлений на уровне страны и областей, а на уровне районов —
**только** `priznak_460=517667` («всего по всем видам»). Это ограничение
первоисточника, не сбора.

### Значение

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `unit_code` | TEXT | Код единицы измерения: `206` единиц, `210` чел., `208` процентов | **Критично**: не дает сложить преступления (единиц) с числом лиц (чел.) или с процентами. 10 показателей в единицах, 18 в людях, 1 в процентах. |
| `unit_name_ru` | TEXT | Подпись единицы | Читается без JOIN. |
| `value` | REAL | Числовое значение; NULL, если портал отдал прочерк | То, ради чего всё затевалось. |
| `value_raw` | TEXT | Исходный токен портала дословно: `85374.0`, `-`, `…` | Разделение «нет данных» и «ноль». Прочерк не превращается в 0 — `value` становится NULL, а токен остаётся здесь. В текущем датасете пропусков нет. |
| `obs_attribute` | TEXT | Атрибут/сноска наблюдения из SDMX-CSV | Зарезервировано под пометки портала (в этом разделе пустое во всех строках — NULL). |

### Провенанс

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `source_window` | TEXT | Окно годов HTTP-запроса, из которого пришла строка: `2010-2019`, `2023-2025` | Портал отдаёт не больше 10 лет за запрос, поэтому период режется на окна. Поле позволяет точно воспроизвести любой запрос и понять, откуда взялась строка. 19 различных окон. |
| `retrieved_at` | TEXT | UTC-метка получения (ISO 8601) | Обязательное требование при цитировании официальной статистики: данные пересматриваются задним числом. |

Полный URL эндпоинта и ссылка на страницу показателя не дублируются в каждой
строке — они выводятся из `indicator_code` и лежат в `indicators.portal_page`.

## 2. `territories` — справочник территорий

374 строки, PK `geo_code`. Полное дерево из SDMX-справочника `CL_razrez_594`.

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `geo_code` | TEXT PK | Уникальный код территории портала | Ключ связи с `facts`. Единственный надёжный идентификатор. |
| `name_ru` / `name_en` / `name_be` | TEXT | Название на трёх языках | en нужен для связывания с внешними границами (OSM/GADM: `Baranovichy district`), be — для белорусскоязычных выгрузок. **Не уникальны**: 5 пар дублей (`г. Барань`, `г. Орша`, `г. Полоцк`, `гп. Болбасово`, `гп. Домачево`). |
| `level` | INTEGER | Глубина в иерархии: 0 страна, 1 область/г. Минск, 2 район, 3 посёлок/сельсовет | Фильтр уровня разреза. Распределение: `{0: 1, 1: 7, 2: 146, 3: 220}`. |
| `level_name` | TEXT | Подпись уровня | Для отчётов. |
| `parent_code` | TEXT | Непосредственный предок. NULL только у корня (`699961`) | Исходная иерархия портала; из неё вычислены `level`, `region_*` и `district_*`. Нужна, если требуется обход дерева вверх/вниз. |
| `region_code` / `region_name_ru` | TEXT | Предок уровня 1 (область) | Denormalized: группировка по областям без рекурсии. NULL у корня. |
| `district_code` / `district_name_ru` | TEXT | Предок уровня 2 (район) | Тот же смысл для районного уровня. NULL у страны и областей (8 строк). |
| `lat` / `lon` | REAL | Координаты центра территории | Заполняются только при `--geocode` (Nominatim/OSM); в текущем датасете NULL во всех 374 строках. Нужны для точечных карт. |
| `n_facts` | INTEGER | Сколько наблюдений в `facts` ссылается на эту территорию | **Самое полезное служебное поле**: сразу видно, что данные есть только по 136 территориям из 374. Остальные 238 (сельсоветы, мелкие посёлки) в справочнике присутствуют, но статистика по ним не публикуется. |

| 919067 | Брестская область | 1 | 699961 | Брестская область | NULL | 665 |
| 919075 | Барановичский | 2 | 919067 | Брестская область | Барановичский | 76 |
| 984146 | гп. Городище | 3 | 919075 | Брестская область | Барановичский | 0 |

## 3. `indicators` — справочник показателей

29 строк, PK `indicator_code`.

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `indicator_code` | TEXT PK | Код показателя, напр. `10108000001` | Ключ связи с `facts` и `dimensions`. |
| `name_ru` / `name_en` / `name_be` | TEXT | Название на трёх языках (берётся из SDMX-структуры) | Переводы живут здесь один раз, а не в 20 тыс. строк фактов. |
| `rubric_code` / `rubric_name` | TEXT | Раздел портала: `10620` = «Статистика правосудия и правонарушений» | Понятно, откуда показатель и как собрать соседние (`--rubric`). |
| `periodicities` | TEXT | Периодичность публикации (`годовая`) | Показывает, можно ли ждать внутригодовых данных. У всех 29 — годовая. |
| `year_min` / `year_max` | INTEGER | Границы доступной истории (9 различных `year_min`: 1990, 1993, 1995, 2000, 2005, 2007, 2008, 2014, 2015) | Сразу видно глубину ряда, не сканируя `facts`. «Число зарегистрированных преступлений» — с 1990 г., «Уровень преступности» — с 2007 г., ДТП — с 1995 г. |

| `unit_codes` | TEXT | Коды единиц измерения показателя (`206` / `210` / `208`) | Быстрая проверка совместимости перед агрегацией нескольких показателей. |
| `n_facts` | INTEGER | Сколько наблюдений собрано | Контроль полноты: `0` означает, что показатель не отдал данных. |
| `portal_page` | TEXT | Прямая ссылка на страницу показателя на портале | Верификация и цитирование: можно открыть и сверить число глазами. |

## 4. `dimension_values` — значения справочников измерений

899 строк, PK **(`codelist_id`, `code`)** — составной, потому что один и тот же
`code` встречается в разных справочниках (код `210` есть в 18 справочниках
единиц измерения, код `9` — в трёх разных).

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `codelist_id` | TEXT | Идентификатор справочника SDMX: `CL_priznak_460`, `CL_razrez_594`, `CL_unit_10108000001` | Первая половина ключа. Связывает значение с измерением через `dimensions.codelist_id`. |
| `codelist_name_ru` | TEXT | Название справочника: «Виды преступлений», «Меры наказания», «Возрастной состав» | Понятно, что за измерение, без обращения к `dimensions`. |
| `code` | TEXT | Код значения, напр. `517692` | Вторая половина ключа. Именно эти коды зашиты в `facts.breakdown_key`. |
| `name_ru` / `name_en` / `name_be` | TEXT | Название значения на трёх языках | Расшифровка `breakdown_key`: `priznak_460=517692` → `кража` / `Theft`. |
| `parent_code` | TEXT | Родительское значение внутри справочника. NULL у 44 корневых записей (по одной на справочник) | Иерархия внутри разбивки: `517668 убийство и покушение на убийство` → родитель `517667 Всего по всем видам преступлений`. **Важно для агрегации**: нельзя суммировать «всего» вместе с его статьями — получится двойной счёт. |

Крупнейшие справочники: `CL_razrez_594` Территория (374), `CL_priznak_536`
Возрастной состав (184), `CL_priznak_ch_573` (152), `CL_priznak_460` Виды
преступлений (20), `CL_priznak_10781` Меры наказания (9).

## 5. `dimensions` — состав измерений показателя

123 строки, PK (`indicator_code`, `dimension_id`). Паспорт SDMX-структуры:
по 3–7 измерений на показатель.

| Поле | Тип | Что значит | Зачем нужно |
|---|---|---|---|
| `indicator_code` | TEXT | К какому показателю относится измерение | Первая половина ключа. |
| `dimension_id` | TEXT | Идентификатор измерения: `razrez_594`, `priznak_460`, `unit_10108000001`, `TIME_PERIOD` | Совпадает с именем колонки в исходном SDMX-CSV и с левой частью `breakdown_key`. |
| `position` | INTEGER | Порядок измерения в структуре (0…6) | Восстанавливает порядок колонок SDMX-CSV и `dimensionOrder` запроса. |
| `name_ru` / `name_be` / `name_en` | TEXT | Название измерения («Виды преступлений», «Меры наказания») | Понятно, что означает очередная часть `breakdown_key`. |
| `codelist_id` | TEXT | Связанный справочник. NULL у `TIME_PERIOD` (29 строк) — у времени нет справочника | Мост к `dimension_values` для расшифровки кодов. |
| `is_geo` | INTEGER 0/1 | Территориальное ли это измерение | Программный признак, по которому пайплайн подставляет отобранные территории. Ручной анализ: какое измерение отвечает за географию. |
| `is_unit` | INTEGER 0/1 | Измерение единиц измерения | Отделить служебное измерение от содержательных. |
| `is_time` | INTEGER 0/1 | Измерение времени | То же. |
| `n_codes` | INTEGER | Сколько значений в справочнике | Мгновенная оценка «насколько детальна разбивка»: 374 у территории, 20 у видов преступлений, 184 у возрастного состава, 0 у времени. |

Пример — показатель `10108000012` «Численность осуждённых»:

| position | dimension_id | name_ru | n_codes | роль |
|---|---|---|---|---|
| 0 | `razrez_594` | Территория Республики Беларусь | 374 | geo |
| 1 | `priznak_536` | Возрастной состав | 184 | разбивка |
| 2 | `priznak_10781` | Меры наказания | 9 | разбивка |
| 3 | `priznak_460` | Виды преступлений | 20 | разбивка |
| 4 | `priznak_462` | Категории лиц | 10 | разбивка |
| 5 | `unit_10108000012` | Единицы измерения | 1 | unit |
| 6 | `TIME_PERIOD` | Time period | 0 | time |

По этой таблице видно, почему у такого показателя `breakdown_key` состоит из
четырёх частей, а данные есть только в целом по стране.

## 7. `errors` — журнал ошибок сбора

0 строк в текущем датасете (прогон прошёл без ошибок). Заполняется, если
портал отклонил запрос или вернул HTTP-ошибку по отдельному окну годов —
при этом сбор **не прерывается**, остальные показатели добираются.

| Поле | Тип | Что значит |
|---|---|---|
| `id` | INTEGER PK AUTOINCREMENT | Порядковый номер записи |
| `indicator_code` | TEXT | Показатель, по которому не удалось получить данные |
| `years` | TEXT | JSON-массив окна годов, например `[2010, …, 2019]` |
| `error` | TEXT | Текст ошибки (`api: …` — содержательный ответ портала, `http 500` — статус) |
| `logged_at` | TEXT | UTC-метка |

Зачем: отличить «на портале нет таких данных» от «запрос не прошёл». Если
таблица непустая, в `facts` будут дыры именно по перечисленным окнам, и их
нужно перебрать (`--years` на конкретный диапазон).

## Связи между таблицами

| Откуда | Куда | По чему |
|---|---|---|
| `facts.indicator_code` | `indicators.indicator_code` | 1:1 |
| `facts.geo_code` | `territories.geo_code` | N:1 (у строк без гео-разреза `geo_code` IS NULL) |
| `facts.breakdown_key` | `dimensions` + `dimension_values` | разбирается по `=` и `,`, затем `codelist_id` + `code` |
| `facts.unit_code` | `dimension_values.code` при `codelist_id = 'CL_unit_' ‖ indicator_code` | N:1 |
| `dimensions.indicator_code` | `indicators.indicator_code` | N:1 |
| `dimensions.codelist_id` | `dimension_values.codelist_id` | 1:N |
| `territories.parent_code` | `territories.geo_code` | самоссылка (дерево) |

Внешние ключи в DDL намеренно не объявлены: данные приходят из внешнего
источника, и жёсткие ограничения мешали бы частичной загрузке. Целостность
обеспечивается на уровне пайплайна.

## Подводные камни при анализе

1. **Не смешивайте уровни иерархии.** `SUM(value)` по всей таблице даст
   многократный двойной счёт: страна содержит области, области — районы.
   Всегда фильтруйте `geo_level`.
2. **Не суммируйте «всего» с составляющими.** Внутри `priznak_460` значение
   `517667` («Всего по всем видам преступлений») — родитель для остальных 12.
   Проверяйте `dimension_values.parent_code`.
3. **Следите за единицами измерения.** `unit_code` 206 (единиц), 210 (чел.),
   208 (процентов) смешивать нельзя.
4. **Детализация по видам преступлений есть только у страны и 7 областей.**
   Районы (128 территорий) дают лишь итог `priznak_460=517667`, и то с 2007 г.
   (у Барановичского района, например, 19 значений: 2007–2025).
5. **Глубина истории различается.** В 1990-х по главному показателю 97 строк
   в год, в 2000-х 104, с 2007 г. — 232 (= 13 по стране + 7×13 по областям +
   128 районов по одному итогу).
6. **Сумма областей ≠ итог по стране в 1990–2011 гг.** (−0,9…−2,9 %),
   с 2012 г. расхождение нулевое. Это особенность первоисточника — часть
   преступлений (транспорт, воинские формирования) не распределялась по
   областям. Проверка лежит в `qa_consistency.csv`.
7. **NULL у `geo_code`** — это не потерянные данные, а показатели, которые
   Белстат публикует только в целом по стране (832 строки, 5 показателей).
8. **Названия территорий неуникальны** — соединяйте только по `geo_code`.

## Примеры запросов

```sql
-- 1. Районы Брестской области, итоги по всем видам преступлений
SELECT t.name_en, f.year, f.value
FROM facts f JOIN territories t ON t.geo_code = f.geo_code
WHERE f.indicator_code = '10108000001'
  AND f.breakdown_key  = 'priznak_460=517667'
  AND f.region_name_ru = 'Брестская область'
  AND f.geo_level = 2
ORDER BY f.year, f.value DESC;

-- 2. Кражи по областям за 2025 год с английскими названиями
SELECT t.name_en, f.value
FROM facts f JOIN territories t ON t.geo_code = f.geo_code
WHERE f.indicator_code = '10108000001'
  AND f.breakdown_key = 'priznak_460=517692'
  AND f.geo_level = 1 AND f.year = 2025
ORDER BY f.value DESC;

-- 3. Расшифровать произвольный breakdown_key
SELECT d.name_ru AS измерение, dv.code, dv.name_ru AS значение
FROM dimensions d
JOIN dimension_values dv ON dv.codelist_id = d.codelist_id
WHERE d.indicator_code = '10108000012';

-- 4. Проверить, по каким территориям вообще есть данные
SELECT level_name, COUNT(*) AS всего, SUM(n_facts > 0) AS с_данными
FROM territories GROUP BY level_name;

-- 5. Средний темп прироста по стране
SELECT year, value,
       ROUND(100.0 * (value - LAG(value) OVER (ORDER BY year))
             / LAG(value) OVER (ORDER BY year), 2) AS pct
FROM facts
WHERE indicator_code = '10108000001' AND geo_level = 0
  AND breakdown_key = 'priznak_460=517667'
ORDER BY year;
```
