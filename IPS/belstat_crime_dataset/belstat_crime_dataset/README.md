# belstat-dataset — сбор агрегированной статистики правонарушений Белстата

Автоматизация **«Варианта 1»**: сбор *официальной агрегированной* статистики
преступности с портала открытых данных Национального статистического комитета
Республики Беларусь — <https://dataportal.belstat.gov.by>.

Каждая строка результата — не отдельное происшествие, а **официальный агрегат**:
`показатель × год × территория × разбивка → значение`. Территориальный разрез —
до **районов и городов областного подчинения** (128 единиц уровня «район» +
7 областей/г. Минск + страна = 136 территорий, по которым портал реально
публикует данные).

Никакого скрейпинга HTML, капч и прокси: портал отдаёт данные по обычному
REST/SDMX-API без регистрации и ключей.

```
19 990 наблюдений · 29 показателей · 136 территорий · 1990–2025 · 132 HTTP-запроса · ~80 секунд
```

## 1. Быстрый старт

```bash
pip install -r requirements.txt          # requests + pandas

# 1) посмотреть, какие показатели входят в раздел «Правосудие и правонарушения»
python -m belstat_dataset discover

# 2) собрать датасет: CSV + SQLite + отчёт о качестве
python -m belstat_dataset collect --years 1990-2025 --out data --db data/belstat_crime.sqlite -v

# 3) посмотреть, что получилось
python examples/quick_analysis.py --db data/belstat_crime.sqlite
```

Полный прогон по всему разделу за 36 лет занимает **~80 секунд** и делает
**132 запроса**. Повторный запуск берёт ответы из кэша и длится ~3 секунды.

Установить как пакет (появится команда `belstat-dataset`):

```bash
pip install -e .
belstat-dataset collect --years 2015-
```

## 2. Что лежит в `data/` после сбора

| Файл | Содержимое |
|---|---|
| `facts.csv` | **Ядро датасета.** 19 990 наблюдений в «длинном» формате (одна строка = показатель × год × территория × значение разбивки). |
| `crime_by_district.csv` | Курируемая таблица по главному показателю «Число зарегистрированных преступлений»: `год × территория × вид преступления`. 6 106 строк. |
| `crime_by_district_wide.csv` | То же в «широком» виде: строки — год × территория, столбцы — 13 видов преступлений. Удобно для ML и Excel. |
| `territories.csv` | Справочник территорий: коды, названия на ru/en/be, уровень, родитель, область, район, `lat`/`lon` (если включён `--geocode`). |
| `indicators.csv` | Справочник показателей: коды, названия на 3 языках, рубрика, периодичность, доступные годы, ссылка на страницу портала. |
| `dimension_values.csv` | Все справочники измерений (виды преступлений, возрастной состав, меры наказания и т. д.) — 899 значений на 3 языках. |
| `dimensions.csv` | Состав измерений каждого показателя (позиция, справочник, роли «гео/единицы/время»). |
| `belstat_crime.sqlite` | Всё перечисленное в одной БД + индексы + таблица `meta` с конфигом прогона. |
| `REPORT.md` | Отчёт о прогоне и контроле качества. |
| `qa_*.csv` | Таблицы проверок: покрытие, динамика по стране, топ районов, сверка «сумма областей vs итог по стране». |

### Схема `facts`

| Колонка | Тип | Описание |
|---|---|---|
| `fact_id` | TEXT PK | sha1 от естественного ключа — делает повторные запуски идемпотентными |
| `indicator_code` | TEXT | код показателя портала, напр. `10108000001` |
| `indicator_name_ru` | TEXT | название |
| `time_period`, `year` | TEXT, INT | период; для годовых данных совпадают |
| `geo_code` | TEXT | код территории из справочника `CL_razrez_594` |
| `geo_name_ru`, `geo_level`, `geo_level_name` | — | 0 = страна, 1 = область/г. Минск, 2 = район, 3 = посёлок/сельсовет |
| `region_code/name_ru` | — | область-предок (проброшена для каждого уровня) |
| `district_code/name_ru` | — | район-предок |
| `breakdown_key` | TEXT | машинный ключ разбивки, напр. `priznak_460=517692` |
| `breakdown_value_ru` | TEXT | человекочитаемое значение, напр. `кража` |
| `unit_code`, `unit_name_ru` | — | единицы измерения (`206` = единиц, `210` = человек, …) |
| `value` | REAL | числовое значение; `NULL`, если портал отдал «прочерк» |
| `value_raw` | TEXT | исходный токен портала (`85374.0`, `-`, `…`) |
| `obs_attribute` | TEXT | атрибут/сноска наблюдения из SDMX-CSV |
| `source_window` | TEXT | окно годов запроса, из которого пришла строка (`2010-2019`) |
| `retrieved_at` | TEXT | UTC-метка получения |

Таблица намеренно нормализована: переводы названий (en/be) и полные подписи
измерений не дублируются в каждой строке, а лежат в словарях — JOIN по
`geo_code`, `indicator_code` и `breakdown_key`.

Пример запроса:

```sql
SELECT t.name_en AS district, t.region_name_ru AS oblast, f.year, f.value
FROM facts f
JOIN territories t ON t.geo_code = f.geo_code
WHERE f.indicator_code = '10108000001'
  AND f.breakdown_key  = 'priznak_460=517667'   -- всего по всем видам
  AND f.geo_level = 2
  AND f.year = 2025
ORDER BY f.value DESC;
```

Полное описание каждой таблицы и каждого поля — в
**[`DATA_DICTIONARY.md`](DATA_DICTIONARY.md)** (словарь данных: типы, смысл,
зачем нужно поле, подводные камни при анализе, примеры SQL-запросов).

## 3. Как устроен API портала (разведка)

Публичной документации у портала нет — кнопка «API» в интерфейсе показывает
уже готовые URL. Поэтому эндпоинты были извлечены из JS-бандла веб-приложения
(`main.*.js`, сервис `OsidsPublicApiService`) и проверены вживую.

**База:** `https://dataportal.belstat.gov.by/osids-public-api`
**Заголовок:** `Accept-Language: ru|be|en` (влияет на язык подписей в JSON-API;
SDMX-структура всегда возвращает все три языка).
**Аутентификация не требуется.**

### Использованные эндпоинты

| Метод и путь | Зачем |
|---|---|
| `GET /rubric/rubricTreeNodeGet/{rubricCode}` | название рубрики |
| `GET /rubric/rubricIndicatorsGet/{rubricCode}` | список показателей рубрики (`10620` = «Статистика правосудия и правонарушений», 29 шт.) |
| `POST /indicator/indicatorSearch` | полный каталог портала (~943 показателя) |
| `GET /indicator/indicatorViewCfgGet/{code}` | доступные годы, дерево территорий, преднастроенный фильтр |
| `GET {SDMX}/indicator/datastructure/SDMX-JSON/{code}` | SDMX-структура: измерения, справочники с `parent`-иерархией, названия на ru/be/en |
| `POST /indicator/indicatorValuesSdmxCsvGet` | **данные**: плоский SDMX-CSV |
| `POST /indicator/indicatorApiInfoGet` | официальные SDMX-URL показателя (для документации) |
| `POST /indicator/indicatorValuesSearch` | таблица ровно в том виде, в котором её рисует сайт (для сверки) |

`{SDMX}` = `.../osids-public-api/sdmx-api` — официально документированный слой
«система-система».

### Тело запроса за данными

```http
POST /osids-public-api/indicator/indicatorValuesSdmxCsvGet
Accept-Language: ru
Content-Type: application/json

{
  "indicatorCode": "10108000001",
  "valuesFilter": {
    "years": [2016, 2017, 2018, 2019, 2020, 2021, 2022, 2023, 2024, 2025],
    "periodicities": [],
    "units": ["206"],
    "dimensionOrder": ["razrez_594", "priznak_460"],
    "dimensionParams": {
      "razrez_594": ["699961", "919067", "919075", "..."],
      "priznak_460": []
    },
    "simbolsAfterComma": null
  }
}
```

Ответ:

```csv
DATAFLOW,razrez_594,priznak_460,unit_10108000001,TIME_PERIOD,OBS_VALUE,OBS_ATTRIBUTE
BELSTAT:10108000001_DATA_FLOW(1.0),699961,517667,206,2023,85374.0,
BELSTAT:10108000001_DATA_FLOW(1.0),919075,517692,206,2023,110.0,
```

### Особенности портала, которые пришлось учесть

1. **Не более 10 лет за запрос.** Иначе портал отвечает
   `400 «Просмотр данных возможен за период не более 10 лет.»`
   → пайплайн режет период на окна (`year_windows()`).
2. **Пустой список = «все значения».** `dimensionParams[dim] = []` означает
   полную разбивку по измерению, а не «ничего не выбирать».
3. **Официальный `sdmx-api/indicator/values/SDMX-JSON` теряет данные.**
   Сервер генерирует наблюдения с дублирующимися ключами — для каждого года
   повторяется один и тот же ключ `"0:0:0:-1"`, а измерение времени в
   `structure.dimensions` отсутствует. При разборе JSON выживает только
   последнее значение. Поэтому для сбора используется экспорт
   `indicatorValuesSdmxCsvGet` (плоский SDMX-CSV, потерь нет), а метод
   `values_sdmx_json()` оставлен в клиенте только для диагностики.
4. **`indicatorSearch` игнорирует строку поиска** и всегда отдаёт весь каталог
   → фильтрация по названию делается на клиенте (`--name-filter`).
5. **URN справочника содержит версию в скобках**
   (`...Codelist=BELSTAT:CL_razrez_594(1.0)`). Наивный парсер
   `Codelist=([^)]+)\)` даёт `CL_razrez_594(1.0` и справочник «теряется»,
   а вместе с ним — английские и белорусские названия территорий.
   Используется `Codelist=([^()]+)\(([^)]*)\)`.
6. **Ошибки приходят текстом, а не JSON.** Например, `200` + строка
   `Код индикатора пустой или отсутствует.` — клиент это перехватывает
   (`_raise_for_plain_error`).
7. **Иерархия территорий** берётся из поля `parent` SDMX-справочника
   `CL_razrez_594` (374 кода), а не из дерева веб-интерфейса: только так
   доступны названия на трёх языках.

## 4. CLI

```
python -m belstat_dataset <команда> [опции]

  discover    список показателей рубрики / по фильтру названия
  api-info    официальные SDMX-URL показателя (то, что показывает кнопка «API»)
  collect     собрать датасет
  report      пересобрать отчёт из уже сохранённых CSV или SQLite
```

Ключевые опции `collect`:

| Опция | По умолчанию | Описание |
|---|---|---|
| `--rubric` | `10620` | код рубрики портала (можно несколько) |
| `--indicator` | — | явные коды показателей (можно несколько) |
| `--name-filter` | — | добавить показатели, содержащие подстроку в названии |
| `--years` | все доступные | `2015-2025`, `2020-` (от 2020), `-2010` (до 2010), `2024` |
| `--geo-level` | `country region district` | `country|region|district|settlement|all` или `0..3`, можно несколько |
| `--out` | `data` | каталог для CSV |
| `--db` | — | путь к SQLite (без опции БД не создаётся) |
| `--main-indicator` | `10108000001` | показатель для курируемых таблиц `crime_by_district*` |
| `--no-pivot` | — | не строить широкую pivot-таблицу |
| `--geocode` | выкл | добавить координаты центров территорий через Nominatim (OSM) |
| `--geocode-all-territories` | выкл | геокодировать весь справочник (374 кода), а не только территории с данными |
| `--max-years` | `10` | размер годового окна запроса |
| `--dim-batch` | `0` | резать большие измерения на батчи по N кодов (предохранитель) |
| `--delay` | `0.6` | пауза между запросами, сек |
| `--retries`, `--timeout` | `5`, `120` | повторы и таймаут |
| `--cache-dir`, `--no-cache` | `.cache/belstat` | кэш сырых ответов портала |
| `--lang` | `ru` | язык подписей в JSON-ответах |
| `--dry-run` | — | показать план запросов, ничего не скачивая |
| `-v`, `-vv` | — | лог INFO / DEBUG |

### Примеры

```bash
# Только районы, последние 10 лет, без SQLite
python -m belstat_dataset collect --geo-level district --years 2016-2025 --out data

# Один показатель + координаты для карты
# (геокодирование идёт через Nominatim с паузой 1 с/запрос по правилам OSM:
#  ~136 территорий с данными ≈ 3 минуты, результат кэшируется)
python -m belstat_dataset collect --indicator 10108000001 \
    --years 2015-2025 --geocode --db data/crime.sqlite --out data

# Добавить к разделу правонарушений показатели про население (для расчёта уровней)
python -m belstat_dataset collect --rubric 10620 --name-filter "Численность населения"

# ДТП и погибшие
python -m belstat_dataset collect --indicator 10108000019 --indicator 10108000020 \
    --indicator 10108000021 --years 2000-

# Что вообще отдаст портал по показателю?
python -m belstat_dataset api-info 10108000012
```

## 5. Регулярное обновление

Сбор идемпотентен: перед вставкой строки `facts` по собираемым показателям
удаляются, поэтому повторный прогон не дублирует данные и работает как
обновление. Годовые данные Белстат публикует раз в год (март–май), так что
оптимальная частота — еженедельно.

```bash
./scripts/update_dataset.sh              # весь раздел
./scripts/update_dataset.sh 2020-        # только с 2020 года
```

`scripts/crontab.example` — готовая строка для `crontab -e`.

## 7. Что показал контроль качества

Из `data/REPORT.md` и `data/qa_consistency.csv`:

* **Разбивка по видам преступлений публикуется только по областям и г. Минску**
  (7 территорий × 13 видов). По районам доступен лишь итог
  «всего по всем видам преступлений» — 128 территорий.
* Глубина истории различается: «Число зарегистрированных преступлений» — с 1990 г.,
  «Уровень преступности на 100 000 человек» — с 2007 г., ДТП — с 1995 г.
* **Сумма областей не совпадает с итогом по стране в 1990–2011 гг.** (−0,9…−2,9 %).
  С 2012 г. расхождение ровно нулевое. Это особенность первоисточника
  (часть преступлений — транспортные, воинские формирования — не распределяется
  по областям), а не ошибка сбора. Проверка `consistency_check()` помечает такие годы.
* Пропущенные значения (`-`, `…`) не превращаются в `0`: `value = NULL`,
  исходный токен сохраняется в `value_raw`.

## 8. Ограничения подхода и правовая заметка

* Это **агрегированная**, а не событийная статистика: узнать, *какое именно*
  преступление произошло, из этих данных нельзя. Для событийного уровня нужны
  «Вариант 2» (СМИ/Telegram + NER) или «Вариант 3» (судебные решения).
* Данные официальные и юридически чистые в сборе, но **публикация производных
  карт** уровня улиц/домов — отдельная история (стигматизация районов).
  Районный уровень, который даёт этот пайплайн, к персональным данным отношения
  не имеет: это агрегаты по ~20–90 тыс. населения.
* Портал — чужой государственный сервис. Не выключайте `--delay`, не поднимайте
  параллелизм и указывайте в `--user-agent` свой контакт. Весь раздел за 36 лет
  собирается 132 запросами — нагружать сервер сильнее смысла нет.
* Данные Белстата — официальная статистика; при публикации указывайте источник
  и дату выгрузки (`retrieved_at` есть в каждой строке).

## 9. Куда расширять

* **Другие рубрики.** `discover --rubric 1060402` (труд), `1063261` (население) —
  код тот же, меняются только коды рубрик. Население по районам понадобится,
  чтобы считать уровни преступности на душу населения самостоятельно.
* **Единицы измерения.** Показатель `10108000002` («Уровень преступности на
  100 000 человек») уже собирается — это готовая нормировка.
* **Геометрия для карт.** `territories.csv` даёт коды и названия районов;
  границы (GeoJSON) берутся отдельно из OSM/GADM, связка — по `name_en`
  (`Baranovichy district`) или по `--geocode`-координатам центра.
