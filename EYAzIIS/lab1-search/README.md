# Информационно-поисковая система

Учебная информационно-поисковая система (лабораторная работа 1, **вариант 7**):
логический поиск по коллекции английских документов, ранжирование по TF-IDF
и оценка качества по официальным метрикам РОМИП'2004.

Система запускается на одном компьютере (главный ПК) и обслуживает клиентов
в локальной вычислительной сети через браузер. Доступ в интернет для работы
не требуется.

| Параметр варианта | Значение |
|---|---|
| Реализация элементов ИИ | Интерфейс с пользователем |
| Сфера применения | Локальная вычислительная сеть |
| Стратегия поиска | Логическая |
| Язык коллекции | Английский |

## Быстрый старт

```bash
cd lab1-search
uv sync                          # либо: pip install -e .
python run.py
```

При запуске в консоль печатаются локальный и сетевой адреса:

```text
Информационно-поисковая система запущена.
  Локально:      http://127.0.0.1:8000
  В сети:        http://192.168.1.20:8000  <- адрес для других ПК
```

Дальше:

1. Положите английские документы `.txt` или `.pdf` в каталог `collection/`.
2. Нажмите **«Переиндексация»** в шапке сайта.
3. Введите запрос, отметьте релевантные документы чекбоксами.
4. Нажмите **«Сохранить оценку»**.
5. Откройте **«Метрики»** — таблицы и графики качества поиска.

Наполнить коллекцию автоматически (нужен интернет, работает один раз):

```bash
python scripts/populate_collection.py --books 4 --clear
```

## Как устроен поиск

### Логический отбор

Запрос сводится к булеву выражению над инвертированным индексом:

| Конструкция | Операция | Пример |
|---|---|---|
| Переключатель «Любое слово (OR)» — **по умолчанию** | дизъюнкция (OR) | `holmes investigation` |
| Переключатель «Все слова (AND)» | конъюнкция (AND) | `holmes investigation` |
| Минус перед словом | отрицание (NOT) | `holmes -watson` |
| Диапазон дат | ограничение по дате добавления | с 2024-01-01 по 2024-12-31 |

По умолчанию используется **OR**: первичный ключ ранжирования — число
совпавших терминов, поэтому документы, содержащие все слова запроса,
всегда стоят первыми, а ниже добавляются документы с частичным совпадением.
Выдача строгой конъюнкции — это всегда начало выдачи дизъюнкции, так что
режим OR ничего не теряет и находит больше.

Текст приводится к нижнему регистру, стоп-слова отбрасываются, к остальным
словам применяется стемминг Портера, поэтому `run` находит и `running`.
Минус распознаётся как отрицание только в начале запроса или после пробела,
поэтому `well-known` не превращается в запрет слова `known`.

### Стратегия с отказами

Методичка указывает, что простейший способ поиска по естественно-языковому
запросу — сведение его к логическому, «как правило, это стратегия с отказами».
Реализованы три отказные ситуации:

* слова нет в словаре коллекции — оно помечается в интерфейсе и не участвует
  в поиске, условие ослабляется до OR по известным словам;
* конъюнкция не дала документов — выполняется переход к OR, выдача
  сортируется по числу совпавших терминов, пользователь получает предупреждение;
* отказы можно отключить (`ENABLE_FALLBACK=0`) — тогда выдача честно пустая.

### Ранжирование

Веса вычисляются при индексировании строго по формулам методички:

```text
B_i   = log(N / P_i)          инверсная частота термина     (формула 1.5)
A_i^j = Q_i^j · B_i           вес термина i в документе j   (формула 1.6)
```

Документы упорядочиваются по убыванию:

1. **число терминов запроса**, найденных в документе;
2. **сумма весов `A_i^j`** по совпавшим терминам;
3. **идентификатор документа** — детерминированный тай-брейк.

Третий критерий обязателен: без него порядок документов с равным весом
зависел бы от порядка обхода множества, а оценки качества стали бы
невоспроизводимыми.

При поиске по «всем словам вместе» первый критерий одинаков для всех
документов, поэтому порядок определяется суммой весов TF-IDF.

## Оценка качества

Реализованы метрики дорожки поиска РОМИП'2004: полнота, точность, F-мера,
средняя точность, точность на уровнях 5 и 10 документов, R-точность
и 11-точечный интерполированный график полнота/точность (TREC).

Сводные показатели вычисляются двумя способами (п. 1.2 методички):
**микроусреднение** — по суммарным количествам документов категорий a, b, c
(именно оно применялось в дорожке поиска РОМИП) и **макроусреднение** —
как среднее по запросам.

> **О полноте.** Разметка выполняется по документам, которые система уже
> нашла, поэтому множество релевантных документов всегда является
> подмножеством найденных: категория `c` равна нулю и полнота составляет
> 1.000 для любого запроса. Это свойство способа оценки (пулинг по выдаче),
> а не ошибка расчёта — так же устроена разметка в TREC. Содержательную
> информацию несут точность, средняя точность, P@5, P@10, R-точность и F-мера.

Расчёт метрик покрыт тестами, включая эталонный пример из методички
РОМИП'2004 (п. 1.3.4) с заранее известными значениями интерполированной
точности.

График полноты/точности повторяет рис. 2 методички: маркерами показаны
фактические срезы выдачи, пунктиром — интерполированные значения TREC.
Сглаживание отключено, потому что интерполированная точность — функция
ступенчатая. Если отметок мало и кривая вырождается в прямую, под графиком
выводится пояснение с причинами.

### Структура базы данных

| Таблица | Назначение |
|---|---|
| `documents` | документы коллекции: заголовок, текст, путь, дата, число слов, ключевые слова |
| `terms` | словарь терминов: `df` = P_i, `idf` = B_i |
| `postings` | инвертированный индекс: `tf` = Q_i^j, `weight` = A_i^j |
| `queries` | запросы пользователя; `params_json` — уникальный ключ разметки |
| `relevance_marks` | экспертные отметки релевантности |
| `query_metrics` | сохранённые оценки качества по каждому запросу |

Сводные показатели не хранятся отдельной таблицей, а пересчитываются из
`query_metrics` при каждом обращении, поэтому не могут разойтись с данными
по отдельным запросам.

## Работа в локальной сети

* Сервер слушает все интерфейсы (`APP_HOST=0.0.0.0`), клиенты работают
  через браузер — установка чего-либо на их машины не требуется.
* База данных открыта в режиме **WAL** с таймаутом ожидания блокировки
  `DB_BUSY_TIMEOUT_MS=15000`: несколько пользователей могут одновременно
  искать и ставить отметки релевантности.
* Соединения создаются с `check_same_thread=False`: FastAPI выполняет вход
  в зависимость, обработчик и выход в разных потоках пула. Это безопасно,
  так как соединение принадлежит одному запросу и не разделяется между
  запросами.
* Переиндексация выполняется **одной транзакцией** `BEGIN IMMEDIATE`,
  а чтение и анализ файлов происходят до её начала. При сбое изменения
  откатываются и коллекция не теряется; отметка, попавшая в момент
  переиндексации, повторяется автоматически.
* Все ресурсы интерфейса (стили, скрипты, библиотека графиков, стоп-слова)
  поставляются с проектом — доступ в интернет не нужен.

При включённом брандмауэре разрешите входящие подключения на порт сервера.

## JSON API

Кроме веб-интерфейса доступны программные endpoints для клиентов локальной сети:

```text
GET  /api/search?q=...&all_words=false&limit=10&offset=0   поиск
GET  /api/status                                           состояние индекса
POST /api/relevance                                        отметка документа
POST /api/relevance-batch                                  групповая отметка
POST /api/select-all                                       отметить всю выдачу
POST /api/deselect-all                                     снять все отметки
POST /api/save-metrics                                     вычислить и сохранить оценки
GET  /api/metrics?offset=0&limit=100                       сохранённые оценки
GET  /api/metrics/summary                                  сводные показатели
GET  /api/pr-curve/{query_id}                              11-точечная кривая запроса
```

Интерактивная документация OpenAPI доступна по адресу `/docs`.

## Тесты

```bash
uv run pytest          # либо: python -m pytest
```

96 тестов покрывают:

* **метрики** — эталонный пример РОМИП'2004 (п. 1.3.4), свойства F-меры,
  граничные случаи, монотонность интерполированной точности, единицы отсчёта позиций;
* **поиск** — значения весов по формулам 1.5 и 1.6, конъюнкция, дизъюнкция,
  отрицание, приоритет числа совпавших терминов над весом, детерминированный
  тай-брейк, стратегия с отказами, фильтр по датам, пагинация,
  режим по умолчанию и свойство «конъюнкция — начало дизъюнкции»;
* **обработку текста** — разбор запроса, дефис внутри слова, стоп-слова,
  стемминг, выбор окна сниппета, экранирование HTML;
* **веб-слой** — доступность страниц, локальность библиотеки графиков,
  полный цикл «разметка → сохранение оценки → графики», достижимость режима OR
  из формы, данные графика (интерполяция и фактические срезы);
* **параллельную работу** — передача sqlite-соединения между потоками пула
  FastAPI, одновременный поиск и разметка из восьми потоков,
  переиндексация во время клиентских записей.

Тестовая коллекция из пяти документов подобрана так, что ожидаемые веса
и порядок выдачи вычисляются вручную по формулам методички.

## Используемые компоненты

| Компонент | Назначение | Особенности применения |
|---|---|---|
| FastAPI + Uvicorn | веб-фреймворк и ASGI-сервер | валидация запросов через Pydantic, автодокументация OpenAPI |
| Jinja2 | шаблоны страниц | автоэкранирование предотвращает XSS |
| SQLite | хранение документов, индекса и оценок | режим WAL для параллельного доступа клиентов |
| NLTK (PorterStemmer) | стемминг английских слов | используется только стеммер; загрузка корпусов из сети не выполняется |
| pypdf | извлечение текста из PDF | файлы без текстового слоя пропускаются |
| Chart.js | графики метрик | подключается локально из `static/vendor/`, без CDN |
| pytest | тестирование | тесты работают с изолированной базой во временном каталоге |

Список английских стоп-слов поставляется в файле `app/stopwords_english.txt`,
поэтому система запускается и работает без доступа в интернет.
